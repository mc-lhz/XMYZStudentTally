# 源站 tally 业务完整实现链路分析报告

> 分析对象：https://xmyzstudent.com 的「tally 选票（实时唱票）」业务
> 依据：本仓库镜像的前端产物（assets/）+ 对线上接口的实测
> 本地复刻实现：见 `tally/app.py`（Flask）+ `tally/static/`（前端最小子集）

---

## 1. 业务画像

tally 是一个**现场实时唱票**系统，典型场景：学校活动现场（歌手大赛、十佳评选）由
工作人员在「控制台」给候选人加/减票，全场观众在「大屏」上实时看到柱状图变化。

三个前台视图（全部来自源站路由表，见 `data/routes.json`）：

| 路由 | 名称 | 页面 chunk | 权限 |
|---|---|---|---|
| `/admin/tally` | admin-tally | `TallyActivitiesPage-Ck1JhJya.js` | requiresAuth + `tally.manage` |
| `/admin/tally/activities/:id/edit` | admin-tally-edit | `TallyActivityEditPage-DFD129SB.js` | requiresAuth |
| `/admin/tally/activities/:id/control` | admin-tally-control | `TallyControlPage-CBBTMqC8.js` | requiresAuth |
| `/tally/screen/:id` | tally-screen | `ScreenPage-D-8ErF3w.js` | **公开（无登录）** |

## 3. 接口契约（12 个端点逐字对应）

REST baseURL：`/api/v2`；统一响应 `{code:200, message, data}`。

| # | 方法 | 路径 | 入参 | data 出参 |
|---|---|---|---|---|
| 1 | GET | `/admin/tally/activities` | — | 活动数组（id/title/status/createdAt，无候选人明细） |
| 2 | POST | `/admin/tally/activities` | `{title}` | 新建活动对象 |
| 3 | GET | `/admin/tally/activities/:id` | — | 活动详情（含 candidates 按 displayOrder 排序） |
| 4 | PUT | `/admin/tally/activities/:id` | `{title? \| status?}` | 更新后的活动（status: 0 待开始 / 1 进行中 / 2 已结束） |
| 5 | DELETE | `/admin/tally/activities/:id` | — | true（级联删除候选人与记录） |
| 6 | POST | `/admin/tally/activities/:id/candidates` | `{number, name, displayOrder}` | 新候选人 |
| 7 | PUT | `/admin/tally/candidates/:id` | `{number?, name?, displayOrder?}` | 更新后的候选人 |
| 8 | DELETE | `/admin/tally/candidates/:id` | — | true |
| 9 | POST | `/admin/tally/candidates/:id/vote` | `{delta}`（≠0，可正可负） | 新操作记录 |
| 10 | POST | `/admin/tally/activities/:id/undo` | — | 刚写入的撤销记录；无可撤销时 `data=null` |
| 11 | GET | `/admin/tally/activities/:id/records` | — | 记录数组（最新在前） |
| 12 | WS | `/ws/tally/activity/:id`（源站：`wss://api.xmyzstudent.com/...`） | — | 见下 |

**WS 快照结构**（实测自线上，字段名与键序均与源站一致）：
```json
{
  "activityId": 4,
  "candidates": [
    {"displayOrder": 1, "id": 11, "name": "陈希望", "number": "1", "voteCount": 220}
  ],
  "status": 1,
  "title": "2026年…学生会主席选举",
  "updatedAt": "2026-09-07 22:35:13.541263128"
}
```
服务行为：连接建立立刻推一帧快照；此后该活动有任何变动（改状态、改标题、
增删改候选人、录票、撤销），向该活动的**所有订阅者**广播新快照。

## 4. 端到端时序

```
大屏/控制台                 后端                        WS 订阅者
   │   WS GET /ws/tally/activity/4 (Upgrade)               │
   │──────────────────────►│ 先发快照 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄▶ 所有订阅者
控制台 POST /candidates/11/vote {delta:+5}                │
   │──────────────────────►│ 票数+5、写记录、更新 updatedAt │
   │◄────── {code:200,...} │ 广播快照 ┄┄┄┄┄┄┄┄┄┄┄┄┄▶ 大屏柱图动画
控制台 GET  /activities/4/records（手动刷新日志，非推送）    │
```

控制台也挂在同一条 WS 上（重用它拿 `title/status/candidates`），录票按钮依据
`status===1` 且已有快照才可用；操作日志单独走 REST #11，每次录票/撤销成功后
主动刷新一次（取前 20 条）。

## 5. 状态机与数据模型

**活动状态机**：`0 待开始 ─(配置页/列表切换)→ 1 进行中 ─→ 2 已结束`；
仅 `1 进行中` 允许录票（前端置灰按钮，后端同样返回 400 兜底）。

**数据模型**（对应 `tally.json`）：

```
Activity  {id, title, status, createdAt, updatedAt, candidates:[Candidate]}
Candidate {id, activityId, number, name, displayOrder, voteCount, createdAt}
Record    {id, activityId, candidateId, candidateNumber, candidateName,
           delta, type(0 普通 | 1 撤销), createdAt}
```

**撤销语义**：取该活动最新一条 `type=0` 的记录，按 `-delta` 回滚票数（下限 0），
再写入一条 `type=1`、delta 为反向值的新记录。**不改变原记录**——历史可追溯，
这就是页面日志中「普通/撤销」徽标的来源。

## 6. 初始数据来源

4 次历史活动（id=1..4）的标题/状态/候选人/票数全部来自对线上
`wss://api.xmyzstudent.com/ws/tally/activity/{1..4}` 的实测抓取
（REST 管理接口需登录态，WS 快照公开，需带 `Origin: https://xmyzstudent.com` 请求头，
否则握手被 403）。抓取脚本存 `tally.json` 为 UTF-8。
