> 接口契约、端到端时序、状态机、数据模型六个维度。

## 1. 业务画像

### 1.1 一句话定义
线下活动（如校园歌手大赛决赛、班级评选）进行**现场唱票**时，工作人员把念出的每一张选票
实时录入系统，同时投放到会场大屏，让全场观众同步看到票数增长的过程。

### 1.2 典型使用场景
1. 活动组织者在 **活动管理页** `/admin/tally` 创建活动并配置候选人；
2. 唱票开始前把活动状态切换为 **进行中（status=1）**；
3. 唱票主持人打开 **唱票控制台** `/admin/tally/activities/:id/control`，
   依念票顺序点击候选人的 `+1/+5/+10/−1` 或输入自定义票数；
4. 会场大屏打开 `/tally/screen/:id`，票数通过 WebSocket **实时跳动**；
5. 唱票结束切回 **已结束（status=2）**，或随时用「撤销上一步」纠错。

### 1.3 关键角色
| 页面                 | 路由                                     | 访问权限 | 一句话职责                             |
|----------------------|------------------------------------------|----------|----------------------------------------|
| 活动管理页           | `/admin/tally`                           | 需登录   | 活动增删改查 + 状态切换 + 大屏链接     |
| 配置活动页           | `/admin/tally/activities/:id/edit`       | 需登录   | 维护候选人（编号/姓名/显示顺序）       |
| 唱票控制台           | `/admin/tally/activities/:id/control`    | 需登录   | 现场录票、撤销、操作日志               |
| 大屏                 | `/tally/screen/:id`                      | 公开     | 实时柱状图展示票数（WebSocket 驱动）   |

## 3. 接口契约（12 REST + 1 WS，与源站逐字对应）

前端 axios `http` 实例的 baseURL 已被本地化改为 `"/api/v2"`，请求统一走前面的 `/api/v2` 前缀。
后端同时注册 `/api/v2/...` 与无前缀两套等效路由，便于直接访问与测试。

统一响应外壳：`{ "code": 200, "message": "ok", "data": ... }`。

| # | 方法 | 路径 | 请求体 | 返回 data | 由前端哪个函数发出 |
|---|------|------|--------|-----------|--------------------|
| 1 | GET  | `/admin/tally/activities` | — | `[{id,title,status,createdAt}]` | tally.zz0 `getAdminTallyActivities` |
| 2 | GET  | `/admin/tally/activities/:id` | — | `{id,title,status,createdAt,candidates[]}` | tally.zz1 `getAdminTallyActivitiesById` |
| 3 | POST | `/admin/tally/activities` | `{title}` | `{id,title,status:0,createdAt}` | tally.zz2 `createAdminTallyActivities` |
| 4 | PUT  | `/admin/tally/activities/:id` | `{title}` 或 `{status}` | 更新后的活动对象 | tally.zz3 `updateAdminTallyActivities` |
| 5 | DELETE | `/admin/tally/activities/:id` | — | `null` | tally.zz4 `deleteAdminTallyActivities` |
| 6 | POST | `/admin/tally/activities/:id/candidates` | `{number,name,displayOrder}` | 候选人对象 | tally.zz5 `createAdminTallyActivitiesCandidates` |
| 7 | PUT  | `/admin/tally/candidates/:id` | `{number|name|displayOrder}` | 候选人对象 | tally.zz6 `updateAdminTallyCandidates` |

## 4. 端到端时序

### 4.1 活动管理
```
运营       活动管理页(/admin/tally)            Flask 后端               tally.json
 |  打开页面  |  GET /api/v2/admin/tally/activities  |                        |
 |----------->|------------------------------------->|  读 activities        |
 |  展示列表  |<-------------------------------------|------------------------|
 |  点「新建」|  POST /api/v2/admin/tally/activities {title}                   |
 |----------->|------------------------------------->|  追加 activity        |
 |  返回新活动|  code:200, data: activity           |  写盘                 |
 |  下拉切状态|  PUT /api/v2/admin/tally/activities/:id {status}                |
 |----------->|------------------------------------->|  更新 status + 触发WS 广播 |
```

### 4.2 现场唱票（核心链路：录票 → 日志 → WS 广播 → 大屏跳动）
```
主持人     唱票控制台(control)     Flask 后端            WS 广播        大屏(screen)
 |  点 +5   |  POST /candidates/:id/vote {delta:5}    |               |            |
 |--------->|---------------------------------------->|               |            |
 |          |  累计候选票数+5，写一条 type=0 记录      |               |            |
 |          |<---- code:200, record                   |               |            |
 |          |  主动刷新操作日志(records)                |               |            |
 |          |  (GET records, 取前20条)                 |               |            |
 |          |                                        | ws push snapshot(voteCount 已+5) |
 |          |                                        |--------------->|  watch 检测到 |
 |          |                                        |               |  票数变化delta=5 |
 |          |                                        |               |  柱子上弹“+5”气泡 |
 |  点撤销   |  POST /activities/:id/undo              |               |            |
 |--------->|---------------------------------------->|               |            |
 |          |  回滚最近一笔(type=0→1)并补一条负向记录    |               |            |
 |          |<---- code:200, data:true                 |               |            |
 |          |                                        | ws push snapshot(voteCount 已还原) |
```

### 4.3 WebSocket 连接生命周期
```
浏览器大屏                                                    Flask 后端
  zz11 拼 URL ws://host/ws/tally/activity/:id
  |  new WebSocket(url)
  |---------------------------------  HTTP GET + Upgrade: websocket  ----------->|
  |<-------------------------------  101 Switching Protocols -------------------|
  |  onopen → connected=true
  |<------- 第一帧：当前全量快照(JSON text) --- 服务器立即推 --------------------|
  |  onmessage → JSON.parse → snapshot
  ... 每次 REST 变更 _broadcast_snapshot 全量推送 ...
  |  (网络抖动) 断开
  |  onclose → connected=false → setTimeout 重连(1s,2s,4s,...封顶30s)
  |-------- 重连 -------> 重新握手 + 推快照（前端立即恢复到最新状态）
```

## 5. 状态机

### 5.1 活动状态机
```
      ┌────────────────────┐
      │ 0 待开始 (pending) │
      └──────────┬─────────┘
                 │ 状态切 1（唱票开始）
                 ▼
      ┌────────────────────┐      PUT /activities/:id {status:1}
      │ 1 进行中 (live)     │ ◄─────────────────┐
      └──────────┬─────────┘                    │（可从 2 切回返工）
                 │ 状态切 2（唱票结束）
                 ▼
      ┌────────────────────┐
      │ 2 已结束 (ended)    │────────────────────┘
      └────────────────────┘
删除任意状态均可（DELETE 级联清理候选人+记录）。
```

| 状态 | 录票（control 页） | 说明 |
|------|--------------------|------|
| 0 待开始 | 禁止（置灰 + 顶部黄条提示） | 尚未开场 |
| 1 进行中 | 允许（唯一可录票状态） | 现场唱票窗口 |
| 2 已结束 | 禁止（置灰） | 唱票结束，可切回 1 返工 |

### 5.2 操作记录状态机
```
type=0 普通录票 ──(被 undo 命中)──► type=1 已撤销（同时追加一条 delta=-原delta 的撤销记录）
   ▲                                    │
   └────── 任一新录票产生 type=0 记录 ───┘
undo 只会回滚「最近一条仍为 type=0」的记录，已撤销记录不可再撤销。
```

## 6. 数据模型（单文件 tally.json）

三个集合存于同一 `tally.json`：

```jsonc
{
  "activities": [   // 活动
    { "id": 1, "title": "2024年校园歌手大赛决赛", "status": 2, "createdAt": "..." }
  ],
  "candidates": [   // 候选人（挂靠 activityId）
    { "id": 1, "activityId": 1, "number": "01", "name": "陈嘉杰",
      "displayOrder": 1, "voteCount": 156 }
  ],
  "records": [      // 操作日志（撤销回滚依据）
    { "id": 1, "activityId": 1, "candidateId": 1, "candidateNumber": "01",
      "candidateName": "陈嘉杰", "delta": 10, "type": 0, "createdAt": "..." }
  ]
}
```

字段含义：
- `status`：0 待开始 / 1 进行中 / 2 已结束（前端徽标 pending/live/ended）
- `displayOrder`：候选人展示顺序，升序排列
- `voteCount`：冗余字段，= 该候选人所有 `type=0` 记录 delta 之和（读快直接用，改时同步累减）
- `type`：0 普通录票 / 1 已撤销；undo 依靠 `type=0 的最后一条` 定位回滚目标

首次启动即含源站 id=1/2/3/4 四次历史活动（歌手大赛、社团投票、学生干部评选、嘉年华摊位），
分别覆盖已结束（status=2）、进行中（status=1）、待开始（status=0）三种状态，便于验收可视化。
