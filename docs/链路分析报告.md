# 源站 tally 业务完整实现链路分析报告

> 分析对象：`https://xmyzstudent.com` 的 **tally（实时唱票）** 业务
> 分析方法：镜像前端产物静态分析 + 线上接口实测（只做只读 GET）
> 分析时间：2026-09-25
> 对应实现：本目录上一级的 `tally/`（本地 Flask 后端 + 镜像前端子集）

---

## 1. 业务画像

tally 是校园双代会 / 主席竞选场景下的**现场实时唱票系统**，三块界面共用一份数据：

| 界面 | 路由 | 使用者 | 数据来源 |
|---|---|---|---|
| 活动管理页 | `/admin/tally` | 管理员 | 管理接口（需登录） |
| 活动配置页 | `/admin/tally/activities/:id/edit` | 管理员 | 管理接口（需登录） |
| 唱票控制台 | `/admin/tally/activities/:id/control` | 计票员 | 管理接口 + WebSocket 快照 |
| 实时大屏 | `/tally/screen/:id` | 投影/投屏 | 公开快照 + WebSocket 快照 |

关键特征：

* **写少读多、读要即时**：一个活动只有一名计票员在录票，但同时有若干块大屏在展示；
  票数变化必须在一秒内覆盖所有大屏 —— 这是它必须用 WebSocket 而不是轮询的根本原因。
* **票是增量而非覆盖**：前端只发 `{delta: n}`，服务端负责累加，因此服务端是票数的唯一权威。
* **撤销是一等公民**：现场录票容易点错，必须能撤销「最近一次操作」，且撤销本身也要留痕。
* **活动状态是三道闸**：`0 待开始 / 1 进行中 / 2 已结束`，只有 `1` 允许录票
  （前端把按钮直接置灰，见 `TallyControlPage` 的 `disabled` 绑定）。

## 3. 接口契约（反推结果 + 线上实测）

axios 实例在入口 chunk 中创建，`baseURL = https://api.xmyzstudent.com/api/v2`，
请求拦截器自动注入 `Authorization: Bearer <localStorage.token>`，
响应拦截器在 HTTP 401 时派发 `auth:token-expired` 事件。

| # | 方法 | 路径 | 前端函数 | 入参 | 出参 `data` |
|---|---|---|---|---|---|
| 1 | GET | `/admin/tally/activities` | `listActivities()` | — | `Activity[]` |
| 2 | POST | `/admin/tally/activities` | `createActivity(title)` | `{title}` | `Activity` |
| 3 | GET | `/admin/tally/activities/{id}` | `getActivity(id)` | — | `Activity & {candidates[]}` |
| 4 | PUT | `/admin/tally/activities/{id}` | `updateActivity(id,patch)` | `{title?,status?}` | `Activity` |
| 5 | DELETE | `/admin/tally/activities/{id}` | `deleteActivity(id)` | — | `true` |
| 6 | POST | `/admin/tally/activities/{id}/candidates` | `addCandidate(id,c)` | `{number,name,displayOrder}` | `Candidate` |
| 7 | PUT | `/admin/tally/candidates/{cid}` | `updateCandidate(cid,p)` | `{number?,name?,displayOrder?}` | `Candidate` |
| 8 | DELETE | `/admin/tally/candidates/{cid}` | `deleteCandidate(cid)` | — | `true` |
| 9 | POST | `/admin/tally/candidates/{cid}/vote` | `vote(cid,delta)` | `{delta}` | `{candidate,record}` |
| 10 | POST | `/admin/tally/activities/{id}/undo` | `undo(id)` | — | 撤销结果 / `null` |
| 11 | GET | `/admin/tally/activities/{id}/records` | `records(id)` | — | `Record[]`（倒序） |
| 12 | GET | `/tally/activities/{id}/snapshot` | 由大屏/读侧使用 | — | `Snapshot`（公开） |
| 13 | WS | `/ws/tally/activity/{id}` | `useTallySocket(id)` | — | 持续推送 `Snapshot` |

**接口总数 = 12 个 REST + 1 个 WS 地址**，与任务书验收标准一致。

### 3.1 线上实测记录（2026-09-25，只读）

```
GET  https://xmyzstudent.com/api/v2/tally/activities/1/snapshot  -> 200
     {"activityId":1,"title":"2026厦门一中思明校区双代会","status":1,
      "candidates":[{"id":1,"number":"1","name":"测试1","displayOrder":1,"voteCount":25}, ...],
      "updatedAt":"2026-09-25T09:11:54.876532558"}
GET  .../admin/tally/activities                                  -> 401 {"code":401,"message":"未授权"}
GET  .../tally/activity/1                                        -> 500（路由存在但后端不可用）
POST .../auth/login {"loginType":"normal","username":"admin","password":"admin"} -> 200 + {"code":401,"message":"用户名或密码错误"}
```

结论与取舍：

* **公开快照接口无需认证**，这是抓取初始数据的合法入口（任务书注明「抓取过程不需要认证」）。
* 管理接口与登录接口均需真实凭据，本地实现无法复用线上数据源，
  因此本地后端**按同一契约自建鉴权**：`POST /api/v2/auth/login`，
  账号 `admin / admin`（可用 `tally/auth.json` 覆盖），token 由后端签发。
* 401 的返回形态被保留：**HTTP 401 + 同一 `{code,message,data}` 信封**，
  与源站实测一致，前端拦截器行为不需要任何修改。

### 3.2 数据模型（本地单文件实现的落库形态）

```
Activity   {id, sourceId?, title, status(0|1|2), createdAt, updatedAt}
Candidate  {id, activityId, number, name, displayOrder, voteCount}
Record     {id, activityId, candidateId, candidateNumber, candidateName, delta, type(0普通|1撤销), undoOf?, createdAt}
Log        {id, activityId, action, detail, createdAt}        # 审计用，前端不展示
```

* `delta` 为增量、`voteCount` 由服务端累加，**大屏只信服务端快照**。
* 撤销不删除原记录，而是追加一条 `type=1` 且 `undoOf` 指向被撤销记录的反向记录 —— 于是票数与日志可双向对账。

## 4. 端到端时序

### 4.1 大屏实时刷新（核心链路）

```
浏览器                 本地服务                      数据文件
  │  GET /tally/screen/1   │
  │ ──────────────────────►│  返回 index.html + 镜像子集
  │                        │
  │  WS /ws/tally/activity/1
  │ ──────────────────────►│  ① 握手升级 101
  │                        │  ② 读 tally.json 生成快照
  │  ◄─────────────────────│  ③ 立刻推一份 snapshot
  │  （渲染柱状图）
  │                        │
计票员点 +5
  │  POST .../vote {delta:5}│
  │ ──────────────────────►│  ④ 累加票数 + 追加 record + 原子写盘
  │  ◄─────────────────────│  ⑤ 广播新 snapshot
  │  （柱高动画推进）        │
  │                        │
网络抖动导致断开
  │  ◄──── onclose ────────│
  │  1s 后重连，失败翻倍至 30s 封顶
  │ ──────────────────────►│  重新握手 → 又收到一份最新快照（自愈）
```

### 4.2 管理侧写操作

```
POST/PUT/DELETE /admin/tally/**  ──►  校验 Bearer token（失败 HTTP 401）
                                     ──►  变更内存数据
                                     ──►  原子落盘 tally.json（tmp + os.replace）
                                     ──►  hub.broadcast(activityId, 新快照)
                                     ──►  返回 {code:200,message:"success",data:...}
```

**每一个写操作都会触发一次广播**，所以大屏不需要知道「谁改了什么」，只需要接收最新快照。

## 5. 状态机

```
                 POST /activities
        ┌────────────────────────────┐
        ▼                            │
   ┌─────────┐  PUT {status:1}  ┌─────────┐  PUT {status:2}  ┌─────────┐
   │ 0 待开始 │ ───────────────►│ 1 进行中 │ ───────────────►│ 2 已结束 │
   └─────────┘                 └─────────┘                 └─────────┘
        ▲                            │                          │
        └────────────────────────────┴──────────────────────────┘
                        PUT {status:0|1|2} 可任意回切

   录票（vote）与撤销（undo）仅在 status == 1（进行中）时前端按钮可用；
   候选人增删改在任意状态均可操作。
```

票数状态机（单候选人）：

```
voteCount ──(+delta)──► voteCount+delta ──(undo 最近一次)──► 回到上一次记录的累计值
   ▲                                                              │
   └───────────── 所有变更都追加 Record，永不物理删除历史 ──────────┘
```

## 8. 已知限制（如实记录）

1. **线上管理接口未抓取**：`/admin/tally/**` 需要真实凭据，401 不可绕过，也无法穷举。
   因此 `tally.json` 的活动元信息（标题/状态/候选人/票数）来自公开快照，
   `description` 之类管理侧字段线上无法确认，本地实现**不引入该字段**，避免编造。
2. **操作记录为合成种子**：源站的历史录票流水不对外公开。
   本地把每个候选人的初始票数写成**一条标记 `seed:true` 的 type=0 记录**，
   保证「操作日志」有据可依且票数可对账；该标记明确区分了「抓取来的」与「现场录的」。
3. **`api.xmyzstudent.com` 当前不可用**：实测 `/api/v2/...` 走该域名返回 502，
   走主站域名才正常（说明主站前置了同源反向代理）。本地实现采用同源策略，与此一致。
4. **WS 只做原样转发**：源站 WS 的鉴权帧、心跳帧格式无法从压缩产物确证，
   本地实现按前端已明确的行为（连上即收快照、收到文本即 JSON.parse）实现，
   额外兼容 `ping`/`pong` 与「客户端主动要快照」，未臆造协议帧。
