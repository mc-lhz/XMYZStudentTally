## 任务一：Tally 选票业务本地实现 — 任务说明

> 适用场景：把线上 `xmyzstudent.com` 的「tally 选票（实时唱票）」业务，在本地用镜像前端 + 自建 Flask 后端完整复刻一遍。
> 本文档可直接作为任务提示词（Prompt）提交给 AI 编码助手，或作为团队任务规格（Spec）归档。

### 1. 项目背景

- **源仓库**：`https://gitee.com/mc_lhz/aitest-using-xmyzstudent/`
- **项目性质**：一个 **SPA 前端项目**，是基于 JS 路由表对线上站点 `xmyzstudent.com` 的**完整前端镜像**（即把源站的前端 HTML/CSS/JS 原样镜像到本地，路由表与源站一致）。
- **前置动作**：先**初步分析项目架构**，定位 tally 相关业务代码与路由。

### 2. 任务目标

在仓库内**新建 `tally/` 文件夹**，在其中开发一个**独立的 Flask 服务器**，本地完整实现「tally 选票（实时唱票）」业务。

### 3. 约束与要求

#### 1. 前端：复用镜像，禁止自研
- 直接**复制并复用**网站镜像中的 `html` / `css` / `js`，**不要自己编写**任何前端代码。
- 以源站前端为准，保证交互与线上一致。

#### 2. 后端：反推接口 + 单文件存储
- 根据网站镜像中 **tally 相关业务 JS 的实现**，**反推其接口契约**（请求路径、方法、出入参），编写**完整的 Flask 后端**。
- 使用**单个 `tally.json` 文件**存储全部活动信息（活动、候选人、票数、操作记录等）。

#### 3. 后端需完整实现三大模块
后端必须覆盖以下三块前端所对应的业务，且**大屏必须使用原网站所用的 WebSocket**：
- **活动管理页**：活动的增删改查、状态切换、列表展示。
- **唱票控制台**：现场录票、撤销、操作日志等。
- **大屏**：实时展示唱票结果，**必须连接源站所使用的同构 WS 地址**（大屏实时刷新靠 WebSocket 推送）。

#### 4. 静态文件：最小化复制
- 复制静态文件时，**仅复制与本业务相关的文件**，**不要复制整站所有文件**。
- 目标是「tally 业务专用的最小前端子集」。

#### 5. 路由规范：与源站同构
- 路由规范与源站**保持一致**，**不需要带 `XMYZStudent` 前缀**。
- 如有 API 相关路由，也**直接拼接在根路由后面**（例如 `/api/v2/...`、`/tally/screen/:id`）。

#### 6. 初始数据：抓取线上四次历史活动
- 源站已有**四次活动**（id 分别为 `1`、`2`、`3`、`4`）。
- 需要**请求 `xmyzstudent.com` 并分析其 JS 代码**，抓取这四次活动的 JSON 数据，写入 `tally.json` 作为**初始数据**。

### 4. 收尾：前端代码治理

完成上述功能后，需对复制过来的 JS 代码进行治理：
- **语义化**变量与函数命名；
- **格式化**代码（统一缩进、换行）；
- 添加**详尽注释**，说明业务含义与接口对应关系。

> 注：源站前端是构建产物（压缩/混淆），治理以「可读化 + 注释」为目标，不改写其渲染逻辑。

### 5. 最终交付物

1. **可运行的本地 Flask 服务**（`tally/` 目录），含前端静态子集与 `tally.json` 初始数据。
2. 一份**《源站 tally 业务完整实现链路分析报告》**，覆盖：
   - 业务画像、前端依赖关系、接口契约、端到端时序、状态机、数据模型。
3. 以本案例为素材，向读者**讲解 WebSocket 前端与后端的相关知识**（升级握手、帧、广播模型、前端重连、心跳等）。

### 6. 验收标准（建议）

- [ ] `tally/` 独立可启动，前端复用镜像文件、非自研。
- [ ] 后端 12 个 REST 接口 + 1 个 WS 地址与源站逐字对应。
- [ ] 活动管理页 / 唱票控制台 / 大屏三块功能完整可用。
- [ ] 大屏经 WebSocket 实时刷新，且 WS 地址与源站同构。
- [ ] 静态文件仅为 tally 相关业务子集（非整站）。
- [ ] `tally.json` 含源站 id=1/2/3/4 四次活动真实初始数据。
- [ ] JS 已语义化、格式化、加注释。
- [ ] 链路分析报告 + WebSocket 教学文档齐备。
